## Release identities

0.5.0.0 as the latest normal version. The upstream pgmq-hs remote had no v0.6 tag;
v0.5.0.0 dereferenced to fc13d7a432dbc0cf0ad4cd3616e5d7d28fdf5abe.

v1.12.0 = 08ace4087dbf00e51704c5a3d9df2e15fd566127 and
v1.13.0 = 32c075bb6dbed66a303d1a792393c93e36c09a97.

unchanged in all six changelogs.

## Validation commands and results

All commands use `nix develop .#partman --command` from this repository unless stated
otherwise. That shell requires pg_partman; the migration test reports PostgreSQL 17.10 /
pg_partman 5.4.3. The existing build directory had a Cabal package-index assertion, so local
candidate validation uses `--builddir=dist-release` without deleting the old directory.

```bash
cabal build all --builddir=dist-release --enable-tests --enable-benchmarks
cabal test pgmq-core pgmq-hasql --builddir=dist-release --test-options=-j2 --test-show-details=direct
cabal test pgmq-migration --builddir=dist-release --test-options=-j1 --test-show-details=direct
cabal test pgmq-effectful pgmq-config --builddir=dist-release --test-options=-j2 --test-show-details=direct
env PGMQ_TEST_SCHEMA_VERSION=1.12.0 cabal test pgmq-hasql --builddir=dist-release --test-options='--pattern "/GroupedHead/ || /Metrics/ || /PartitionCompatibility/" -j2' --test-show-details=direct
env PGMQ_TEST_SCHEMA_VERSION=1.12.0 cabal test pgmq-effectful pgmq-config --builddir=dist-release --test-options='--pattern compatibility -j2' --test-show-details=direct
```

Native counts: core 12, hasql 88, migration 11, effectful 38, config 26. Compatibility
counts: hasql 14, effectful 9, config 6. All passed. The migration command must use one
worker: a blanket -j2 caused shared-database resets to race, and was corrected without
weakening any assertion. Extracted-package native runs pass the same counts using
published pg-migrate 1.1.0.0 dependencies instead of the local development override.

Both umbrella witnesses compile with the package's compiler extensions and selected package
IDs. Temporary copies omitting readGroupedHead fail with “Variable not in scope”, then compile
when the export is restored. No mutation of the shared consumer source tree was needed.

The Shibuya adapter itself passes 161 examples. Its combined project test run also exposed
hasql fixture collisions and NUL generation during shrinking; the final candidate widens
random queue suffixes to Word64 and removes NUL from generated JSON text. The affected
native, consumer and extracted-package tests all pass 88 cases after this correction.

Keiro's mechanical benchmark repair is commit `e03e92df` in mori://shinzui/keiro.
Its full component build passed. Initial test environments exposed two consumer requirements:
Z3 is mandatory for symbolic conformance, and native schema snapshots require PostgreSQL 18
(the checker explicitly rejects 17). Keiro's own `nix/haskell.nix` declares both tools.
That path is relative to mori://shinzui/keiro; its artifact-level URI is pending.
The corrected environment uses the consumer's locked PostgreSQL 18 with pg_partman and Z3:

```bash
export PGMQ_RELEASE_KEIRO_ROOT="$(mori path mori://shinzui/keiro | tail -1)"
nix develop .#partman --command nix shell --impure --expr '
  let f = builtins.getFlake (builtins.getEnv "PGMQ_RELEASE_KEIRO_ROOT");
      pkgs = import f.inputs.nixpkgs { system = builtins.currentSystem; };
  in [ pkgs.z3 (pkgs.postgresql_18.withPackages (ps: [ ps.pg_partman ])) ]
' --command sh -c 'cd "$PGMQ_RELEASE_KEIRO_ROOT" && cabal --project-file=cabal.project.release-candidate test all --test-show-details=direct'
```

The existing consumer project settings and source pins remain unchanged; only temporary
validation files supply local candidate packages and the pgmq development driver pins.

Keiro's compiler/CLI fixtures invoke nested `cabal exec` and `cabal list-bin`. Cabal does not
inherit the parent's `--project-file`, so those subprocesses initially tried Hackage and
rejected unpublished 0.6. Validation supplies a temporary PATH wrapper: preserve an explicit
`--project-file` argument when present, otherwise inject the absolute candidate-project file.
The wrapper forwards all arguments unchanged to the real Cabal executable. It is a local test
artifact, never a repository dependency pin. This keeps generated-code compilation and CLI
binary lookup on the same local package IDs as the outer solver plan.

Keiro's PostgreSQL 18 run executed 55 suites: 52 passed initially. The remaining suites were
operations (nested Cabal lookup), DSL (nested compiler commands), and the main runtime suite
(one nested compiler command plus one 100 ms cutover fault-injection timeout). With the
candidate wrapper, all 48 operations examples and all 16 mkEventStream examples pass. The
single schema-versioned release fault-injection example also passes in isolation; under the
combined load it returned SQLSTATE 57014 instead of the expected classified lock deadline.
No timeout assertion or runtime error handling was weakened to obtain the retry result.

The Keiro PGMQ suite reports 58 examples, zero failures and two pre-existing pending examples:
transient poll fault injection and live partition provisioning in its fixture without
pg_partman setup. These are not counted as executed partition acceptance. This release's
mandatory populated upgrade, spill recovery, premake and config adapter cases execute in
the owning pgmq suites with required pg_partman. Keiro migrations (36 examples), Jitsurei
(25 examples), queue runtime conformance and the local Shibuya adapter (161 examples) pass.

The complete DSL rerun passes all 719 examples with the candidate wrapper, including generated
conformance mutation checks. Across the 55-suite project run and explicit retries, every
reported failure is cleared. The runtime cutover result is an isolated retry, not a claim
that the original combined run was entirely green. Temporary consumer project overrides
were moved out after validation; no machine-local project or wrapper is committed.

The Keiro rollout is committed as `e4ec781b` in mori://shinzui/keiro, following the
separate benchmark repair `e03e92df`. Its unrelated pre-existing documentation edits remain
