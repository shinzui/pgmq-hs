Tasty reports explicit no-op skip branches as passing cases; the stock hasql number therefore
includes four skips, rather than claiming 120 stock behaviors executed. One skips the local
partition re-entry contract, and three skip native alias/mixed-case hardening. The normal
partition silence and ordinary nonzero-throttle cases execute on stock 1.12. No partition
availability skips occurred: the partman shell sets `PGMQ_REQUIRE_PARTMAN=1`.

Dedicated native installers do not become stock tests when the surrounding suite selects
1.12: hasql's `AliasingSpec`, `MixedCaseRemediationSpec` and `InspectionForeignNameSpec`,
effectful's `DisconnectSpec`, and config's `NotifyCrashSpec` and `ForeignQueueSpec` retain
native-only evidence. The new collision fixtures, partition configuration fixtures and
normal partition-notification cases honor the schema selector. This matrix proves the
schema-selectable paths on both schemas without attributing dedicated native fixtures to stock.

The serial migration suite proves fresh installation, history imports, both catalog checkpoints
and the populated six-to-seven-entry upgrade. The latter first receives a leaf notification
under the six-entry ledger, then applies six `AlreadyApplied` results and only 0007 as
`AppliedNow`. It preserves message IDs/payloads, all trigger identities and throttle settings;
without any enable/reconcile call, new partition inserts become silent on parent and every
leaf channel while ordinary delivery continues. A second run reports all seven already applied.
Historical partition upgrade checkpoints remain at six. Catalog exceptions remain the same
three local function bodies.

Native alias cases prove metadata-only and throttle-backed leaf aliases cannot notify or
advance timestamps. Every partition listener has an ordinary-queue liveness control.
Ordinary inserts retain nonzero throttling, and the real crash fixture delivers with its
throttle row lost, then restores the declared 3,600,000 ms interval through explicit
reconciliation without restarting the application. Config acceptance covers single/multiple
aliases, repeated runs, exact ownership, unrelated configs, both drift directions, and
unsupported existing throttle rows. Both new report constructors have explicit golden/parity
cases; the previous domain goldens are unchanged.

All five root creators passed five focused tests each: creation, tightening an owned 0755
directory with a surviving sentinel, repeat calls, unchanged regular-file rejection and
symlink rejection without chmod of its target. Normal suite startup changed the shared
uid-501 root from 0755 to 0700 while retaining inode 71275968 and the existing registry
inode 71275969. Subsequent suites reused it. No shared root or registry was deleted.
A private foreign-owned fixture could not be constructed without privileges; the owner check
before chmod was inspected, and this unavailable optional scenario is not counted as a pass.
